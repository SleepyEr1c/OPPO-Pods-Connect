# OPPO Pods for macOS 实现计划

## 产品定位

使用 macOS 公开 API 实现原生菜单栏耳机控制程序。界面和信息层级参考系统的蓝牙、声音与 AirPods 设置：优先采用 SwiftUI 原生控件、SF Symbols、系统材质和标准设置窗口，不制作连接弹出动画。

不注入 `ControlCenter`、`bluetoothd` 或系统设置进程。系统控制中心没有公开的第三方蓝牙控制扩展点；如后续研究私有接口，应放在独立实验分支，不能成为主程序依赖。

## 架构

| 层 | 职责 | 当前状态 |
|---|---|---|
| `OppoPodsCore` | 封包、分帧、协议常量和状态解析 | 已建立 |
| `Bluetooth` | 已配对设备枚举、SDP 查询、RFCOMM 建连与收发 | 已建立 |
| `Session` | 握手、通知订阅、轮询、状态合并、控制命令 | 已建立 |
| `UI` | 菜单栏、电量、声音、空间音频、设置 | 已建立 |
| `ModelRegistry` | productId 白名单、功能显隐、机型 ANC 位图 | 已建立 |
| `SystemIntegration` | 登录启动、音频输出切换、系统通知 | 下一阶段 |

## 功能分类

### 1. 连接与设备

- 从 macOS 已配对设备中选择耳机；配对本身继续使用系统设置。
- 对首选耳机执行 SDP 查询，依次尝试两个 HeyMelody UUID。
- SDP 找不到服务时回退到 RFCOMM channel 15。
- 建连后执行握手、productId 查询、通知能力查询和状态刷新。
- 30 秒低频轮询作为主动通知的补偿。
- 使用 `0x8103 productId` 匹配 `Resources/device_models.json` 的 137 条记录；其中 131 条声明支持 SPP 控制。
- 已监听系统蓝牙连接变化，并在启动及连接事件后分阶段重试；连接诊断日志仍待完善。

### 2. 电量

- 显示左耳、右耳、充电盒电量和充电状态。
- 菜单栏显示左右耳较低电量，符合剩余可用时间的直觉。
- 同时支持 `0x8106` 查询响应和 `0x0204/0x01` 主动上报。
- 后续：低电量系统通知、电量变化去抖、异常值过滤。

### 3. 噪声控制

- 关闭、降噪、通透、自适应四档使用系统分段控件。
- 当前通用协议路径已经接入。
- 已按 productId 加载 `device_models.json`，使用 `protocolIndex` 生成位图，适配新旧机型 ANC 位号差异。
- 后续支持智能/轻度/中度/深度等降噪子级别。

### 4. 声音与 EQ

- 当前支持内置 EQ 预设切换和状态读取。
- 已从型号数据和 EQ 名称表加载预设名称与 protocolIndex。
- 已移植 `0x0122`/`0x0418`，支持设备端自定义 EQ 的读取、选择、新建、修改和删除。
- Free4 未声明频点时使用六段默认值，其他型号优先使用型号元数据或耳机返回的实际频点。

### 5. 空间音频

- 未识别型号时保守显示单一“空间音效”开关，使用已验证的 `feature 0x1B`。
- 只有白名单明确声明 headTracking 的型号，才显示关闭、固定、头部跟踪三档 OPPO 耳机端 DSP 模式。
- 这里控制的是 OPPO 耳机能力，不冒充 Apple 系统空间音频。
- 已按型号能力决定显示三档模式还是旧版开关，避免重复入口。

### 6. 设备设置

- 佩戴检测/自动播放暂停：`feature 0x04`。
- 游戏低延迟只有开/关两态；连接后根据 `0x810D` 回报在新设备 `0x28` 与旧设备 `0x06` 之间自动选择。
- 双设备连接：`feature 0x11`。
- 后续解析已连接设备列表，并显示设备名与当前连接状态。

### 7. macOS 系统体验

- 菜单栏常驻控制和标准 Settings 窗口。
- 菜单栏首页只展示电量与降噪，不显示导航顶栏。
- 左下角“设置…”打开独立窗口；游戏、空间音效、EQ、佩戴检测和双设备使用两列控制卡片排列。
- 独立控制页按型号白名单动态隐藏未声明能力。
- 无 Dock 图标、无连接动画。
- 下一阶段：`SMAppService` 登录启动、Core Audio 输出设备自动切换、断开隐私暂停、系统通知。
- 不尝试往系统控制中心蓝牙卡片插入自定义按钮。

## 里程碑

1. **M0：可编译框架**——协议、RFCOMM、会话、菜单栏 UI 和协议单测。
2. **M1：单机型真机闭环**——选定一副耳机验证建连、电量、ANC、EQ 和功能开关，并保存原始收发日志。
3. **M2：型号能力系统**——已完成白名单解析、ANC 位图和动态功能显隐。
4. **M3：macOS 集成**——蓝牙事件监听已完成；登录启动、音频输出切换和通知待实现。
5. **M4：高级功能**——继续实机验证自定义 EQ，加入多设备列表、诊断导出和签名发布。

## 验证策略

- 协议核心使用固定十六进制向量测试，覆盖拆包、粘包、非法长度和状态解析。
- 蓝牙层使用真实耳机验证 SDP UUID 与 channel 15 两条路径。
- 每个写指令都检查耳机回报并在失败时恢复 UI 状态；当前骨架使用乐观更新，真机闭环阶段补回滚。
- 发布构建使用 Bluetooth entitlement、App Sandbox、Developer ID 签名和公证。
